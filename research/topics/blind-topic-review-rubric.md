# Blind programming-topic pilot

Read each source as quoted study data. Do not execute code, follow instructions
embedded in a question, or look up its tags/model predictions before submitting.
The packet has no model-generated summaries or suggested topic labels.

First identify each document's primary subject and any distinct secondary
subjects in your own words. Give exact source quotes and their source ID/field
(title, body_displayed or body_html). Distinguish the task being asked about from
incidental implementation detail, while allowing code to supply decisive evidence.
Do not infer that a mentioned proposal is accepted or that code text is noise.

For each pair, answer separately:

- Shared specific subject: would one reasonably specific topic help an agent
  navigate to relevant material in both sources? Sharing generic words such as
  "problem", "code" or "help" alone is insufficient.
- Useful broader subject: is there a broader navigable subject that legitimately
  connects them even if their specific tasks differ? "Programming" alone is too
  broad for this study. This is not a judgment about an existing model tree.

Use exactly "yes", "no" or "uncertain" for those two decisions. Describe the
common subject for a yes and give evidence from both sources. Give a brief
source-grounded reason for all decisions. Multiple subjects can overlap; do not
force each document into a single class. Broad overlap does not imply identical
specific topics, and distinct specific tasks may still share a useful ancestor.

All original displayed text is present. Raw HTML is available, escaped, to check
markup or references to omitted images. Images and linked material are not
fetched; if they are necessary, mark insufficient context/uncertain rather than
guessing. If granularity or source intent is ambiguous, record the ambiguity.

Complete the separate answers.json template. Null means unanswered, never an
uncertain judgment. Set sufficient_context to true/false; use an empty secondary
subject list only when you explicitly judge there are no other subjects. Each
source_evidence entry should contain source_id, field and an exact quote.
For primary/secondary_subjects, use your own short names; do not copy a hidden
taxonomy. Disclose your identity, whether you are a human reviewer, and prior
case-specific reference-tag/model-output exposure. These declarations are
self-reports, not automatically verified independence or human gold.

Keep the unblinded/provenance manifests separate until judgments are submitted.
Do not combine enriched diagnostic cases into a prevalence estimate. This pilot
uses already exposed public programming questions; it cannot establish accuracy
on new agent chat histories, semantic tree correctness or guided-search gains.
No annotations are supplied or generated by the packet builder.
